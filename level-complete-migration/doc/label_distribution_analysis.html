Generated 2026-05-21  |  BHV sample: 153,092 rows (10 shards)  |  CTX sample: 209,719 rows (10 shards)  |  UL sample: 877,366 rows (20 shards)

🔴 Headline Findings

F-1 · Label column semantics are identical across all three datasets: label = did the user complete any level_complete event within the observation window. BHV: 36.06%, CTX: 35.98%, UL: 38.16%. These match — NOT the source of the inflation.
F-2 · The training target differs fundamentally: Legacy trains on per-event labels from the prob_sdk_event_name_labels array (~14.04% for specific events). UL trains on prob_sdk_event_name_label (14.25% overall — but 26.10% for wildcard '*' rows vs 14.30% for specific events).
F-3 · Wildcard '*' rows have dramatically higher positive rates in BOTH datasets, but affect UL far more by row volume: BHV wildcard: 37.75% positive (40% of game-event pairs). UL wildcard: 26.10% positive (11% of unique pairs, but 44% of training rows by volume per BQ analysis). UL model has no post-hoc calibration to correct this.
F-4 · 23.91% of UL training rows have label=1 but prob_sdk_event_name_label=0: The user fired some level_complete event (label=1) but not the campaign-targeted event. These rows contribute zero positive signal for the target event while still being present in training. This is a data quality issue absent from legacy.

3. UL Internal Conflict: label vs prob_sdk_event_name_label

A row with label=1, prob_label=0 means: the user completed some level_complete event (so label=1), but NOT the specific event that this training row targets (prob_label=0). These rows provide a contradictory signal if the model sees both columns.

⚠ 23.91% of all rows (label=1 but prob_label=0): the user completed a level_complete event but not the targeted event. These are noise rows for per-event training — absent from legacy.

7. sdk_event_name Distribution Comparison

Legacy BHV — sdk_event_name

100% of legacy rows have sdk_event_name = "placeholder". The specific event is embedded in prob_sdk_event_name_array instead. This is a fundamental architectural difference: the legacy model does NOT receive the event name as an input feature at request time via this column.

UL — sdk_event_name

UL uses the actual event name as an online-available sparse feature. The event name embedding is critical for per-event calibration — but undertrained for rare events due to wildcard dominance in training.

9. Recommended Fixes (Priority Order)

  1. Enable calibration (enable_calibration: true) — immediate fix, no retraining needed. Applies post-hoc Platt scaling to align serving predictions with true event rates.
  2. Migrate campaign BQ query to campaigns_v3 with archived_at IS NULL filter — eliminates ~2,202 archived campaigns (27.5%) that generate dead wildcard rows.
  3. Explode multi-event campaigns (Path B) instead of collapsing to '*' — the 28 multi-event campaigns produce one row per event with the correct label instead of a wildcard.
  4. Re-enable Stage 5 filter (filter_min_dates_by_game_and_event) — removes cold-start noise rows from before the first positive conversion per (game, event).
  5. Add training data quality checks: fail datagen if any event has >95% pos_rate (wildcard contamination signal) or wildcard share exceeds 30% of total rows.

POST-FIX ANALYSIS — New UL Data (2026-05-12)

Generated 2026-05-21  |  Fix: probabilistic sampling (Stage 6) replaces explode  |  New UL sample: 318,480 rows (20 shards, date=2026-05-12)  |  Old UL sample: 877,366 rows (20 shards, date=2026-05-11)

Verdict: Did the Fix Work?

PARTIALLY FIXED — Wildcard dilution is working. The core mechanism (probabilistic sampling) is functioning as designed. Wildcard row fraction dropped from 44% → 23.18% and wildcard positive rate dropped from 26.10% → 16.49%. The wildcard-to-specific inflation ratio narrowed from 1.8x to 1.33x. Training label distribution is materially closer to the true per-event rate.
Overall prob_sdk_event_name_label positive rate: 13.36% (down from 14.25%). Now within 1pp of the ~14% BHV legacy target.
RESIDUAL ISSUE — Wildcards still 23% of training rows. With sampling, wildcard frequency is proportional to its share of each game's event array. Games with small event sets (e.g. 1 specific + 1 wildcard = 50% wildcard probability) contribute disproportionately. Wildcard pos_rate (16.49%) is still 4pp above specific (12.42%).
RESIDUAL ISSUE — label=1 but prob_label=0 noise reduced but present. 18.55% of rows (down from 23.91%) have label=1 but prob_label=0 — the user fired some level_complete event but not the targeted one. This is structural and cannot be fully eliminated without calibration.
NO CALIBRATION — enable_calibration: false still applies. Even with diluted wildcard rows, the model will still serve slightly inflated predictions. Post-hoc calibration remains the cleanest remaining fix.

Remaining Work (Priority Order)

  1. Enable post-hoc calibration — Residual wildcard inflation (1.33x ratio) will persist as long as enable_calibration: false. This is the cleanest remaining fix. Requires setting up calibration_config with a BQ query returning observed vs predicted rates per (country, platform, model_name).
  2. Per-epoch resampling (long-term) — Currently sampling is fixed at datagen time (equivalent to legacy probabilistic_cache_dataset=True). True per-step resampling (like legacy default) would require BatchCreator to support padded array labels in offline_only_features(). Lower priority — datagen-time sampling is already a significant improvement.
  3. Monitor wildcard pair distribution — The 23% wildcard row fraction depends on campaign event array sizes. If new campaigns add many wildcard-only entries, the fraction will grow back. Add a datagen assertion: fail if wildcard row fraction > 30%.
